## 1. 概述

EmberHub 是一个**模拟器游戏启动器**，参考天马G / Pegasus 的资源组织方式。
它本身**不实现模拟功能**，只做两件事：

1. **按需下载**：从资源服务器下载玩家选中的游戏 ROM，以及该平台所需的模拟器
2. **启动游戏**：用下载好的模拟器打开对应 ROM

核心体验：**打开即游戏库；点游戏 → 缺什么下什么 → 启动；全程不需要用户配置模拟器。**

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| 资源服务器 | 存放 `Roms` 与 `Emulators` 的服务器，**仅支持两种：FTP、OpenList(WebDAV)** |
| Roms | 游戏资源，天马G / Pegasus 格式，按平台分文件夹 |
| Emulators | 模拟器资源，按平台打包的压缩文件，含带版本的配置文件 |
| 平台 | 游戏机种，如 GBA、NES、PS1、街机等 |
| 按需下载 | 只下载玩家当前要玩的游戏及其平台模拟器，不预下载全部 |

## 3. 资源服务器

### 3.1 支持的协议（仅两种）

| 协议 | 说明 | 状态 |
|---|---|---|
| **OpenList / WebDAV** | 已实现（PROPFIND 列目录 + GET 下载） | ✅ 已有 |
| **FTP** | 自建 FTP 服务器 | ❓ 待实现（账号/匿名/FTPS？见 §8） |

### 3.2 服务器根目录结构

```
<资源服务器根>/
├─ Roms/                     # 游戏资源（天马G 格式）
│  ├─ GBA/
│  │  ├─ metadata.pegasus.txt
│  │  ├─ xxx.gba
│  │  └─ media/...
│  └─ NES/
│     └─ ...
└─ Emulators/                # 模拟器资源（按平台打包）
   ├─ GBA/...
   └─ NES/...
```

### 3.3 Roms 结构（天马G / Pegasus 格式）

- 每个平台一个文件夹，内含 `metadata.pegasus.txt`
- 元数据字段参考 Pegasus：`collection` / `game` / `file` / `developer` / `genre` /
  `players` / `release` / `rating` / `description` / `assets.*`
- 封面素材：`media/<游戏名>/boxFront.*`
- 已在 EmberHub 实现解析与展示

### 3.4 Emulators 结构 ❓ **（关键未知，需你补充）**

需要你给出一个**真实示例目录树**，例如：

```
Emulators/
├─ GBA/
│  ├─ ???.zip            # 模拟器压缩包（命名规则？）
│  └─ ???.json / ???.ini # 配置文件（文件名？格式？）
└─ NES/
   └─ ...
```

需要明确：

- ❓ 压缩包命名规则（如 `GBA.zip` / `retroarch-gba-v1.2.zip`？一个平台一个还是多个？）
- ❓ 配置文件文件名与格式（JSON？INI？）
- ❓ 配置文件字段，至少需要：
  - ❓ 版本号（字段名？格式？）
  - ❓ 可执行文件路径（解压后从哪里启动？）
  - ❓ 启动参数模板（是否含 `{file.path}` 占位符？）
  - ❓ 目标平台/系统（PC？Android？如何区分？）
- ❓ 压缩包解压后的目录结构（解压到哪里？根目录还是子目录？）

## 4. 功能一：按需下载

### 4.1 下载 ROM

- 玩家点开游戏 → 若本地没有该 ROM → 从资源服务器下载
- 下载完成后交给模拟器启动

### 4.2 下载模拟器（按平台）

- 玩家点游戏 → 确定其**平台**
- 若该平台模拟器**尚未下载** → 先下载该平台的模拟器压缩包并解压
- 若已下载 → 检查**版本**，必要时更新
- ❓ 版本比对依据：本地版本从哪读？服务器版本从哪读？

### 4.3 下载目录

- 有**默认目录**，但**允许用户修改**
- ❓ 默认目录具体位置？（如 `EmberHub/data/` 下？系统应用数据目录？）
- ❓ 下载/解压后的目录结构？（是否镜像服务器结构？）
- ❓ ROM 与模拟器是否放不同目录？

### 4.4 其他

- ❓ 是否需要下载进度显示？断点续传？多线程？
- ❓ 是否校验完整性（大小 / 哈希）？
- ❓ 缓存清理策略（手动清理？容量上限？）
- ❓ ROM 若为压缩包（zip/7z），是否自动解压？

## 5. 功能二：启动游戏

### 5.1 平台 → 模拟器 的确定

- 根据游戏所属**平台**，找到对应的模拟器
- 模拟器来自 §4.2 的按需下载结果

### 5.2 启动命令来源 ❓

需要明确用哪套命令启动：

- ❓ A. 用 `Roms/<平台>/metadata.pegasus.txt` 里的 `launch:` 字段（现在实现的方式）
- ❓ B. 用 `Emulators/<平台>/` 配置文件里定义的启动命令
- ❓ C. 两者结合（如配置文件给可执行文件，metadata 给参数）

### 5.3 生命周期

- EmberHub **不管理模拟器生命周期**：拉起进程后即放手
- 不主动关闭、不重启模拟器
- ❓ 是否需要复用同一模拟器实例（不重复开窗）？

## 6. 界面与交互

- 打开即**游戏库**（全屏，按平台分类）
- **F1** 打开设置（存储源 / 下载目录等），**Esc** 关闭
- ❓ 下载中的界面表现（进度条？提示？后台？）
- ❓ 是否需要手柄导航（主机式操作）

## 7. 目标平台

- **PC（Windows）优先**
- **Android 以后**
- ❓ Android 端模拟器是 APK（需安装）还是压缩包？平台标识如何区分 PC / Android？

## 9. 非功能需求

- 体积小（Tauri 产物几 MB）
- 启动快
- 离线可玩已下载的游戏
- 配置透明、可手动修改
